OS-01 进程调度分析

凸包顶点 · 操作系统 | 考频：1 次综合题（2026 首次）+ 选择题常驻 | 难度：★★★ 定位：凸包最左顶点——2026 年新增的"边界哨兵"，标志 OS 从"写代码"扩展到"做分析"。

一、为什么它是凸包顶点

进程调度此前只考选择，2026 年首次以分析型综合题出现。它把凸包左边界 从"零基础"推到"会算会分析"：甘特图 + 指标计算 + 算法比较，是典型的 "投入小、回报稳"的新顶点。

二、核心知识清单

2.1 调度算法家族

算法 规则 优点 缺点 抢占?
FCFS 先来先服务 按到达次序 简单、公平 护航效应，短作业吃亏 否
SJF 短作业优先 运行时间最短先 平均周转最优 长作业饥饿，需预知时间 可（SRTF 最短剩余时间优先）
优先级 优先数高先 灵活 饥饿 → ** aging 老化** 均可
时间片轮转 RR 每进程跑一个时间片 q 响应好 q 大退化为 FCFS，q 小切换开销大 是
高响应比 HRRN 响应比 R=(等待+服务)/服务 最大先 兼顾长短 每次调度要计算 否
多级反馈队列 多级队列 + 时间片递增 + 降级 综合最好（实际系统用） 复杂 是

2.2 指标计算（必考公式）

周转时间   = 完成时间 − 到达时间
带权周转   = 周转时间 / 实际运行（服务）时间
平均周转   = Σ周转 / n
等待时间   = 周转时间 − 运行时间（− 阻塞时间）

2.3 甘特图——一切分析的原点

| P1 | P2 | P1 | P3 |
0    2    5    9    12

画对甘特图，所有指标都是读图说话。注意抢占点：新进程到达时重新比较。

2.4 上下文切换

  • 切换内容：保存/恢复 PCB 中的现场（PC、寄存器、栈指针等）；
  • 切换是有代价的——时间片太小，切换开销占比飙升；
  • 进程切换 vs 线程切换：线程切换（同进程内）不换地址空间，代价小。

三、典型考法（2026 型）

  1. 给一组进程的到达时间/运行时间，指定算法（常为 RR 或抢占式优先级）；
  2. 画甘特图 → 求每个进程的周转/带权周转 → 求平均值；
  3. 比较两种算法的优劣，或分析"时间片取何值合适"。

答题流程：

列出进程表 → 按算法规则推演就绪队列 → 画甘特图（标注每次调度决策原因）
→ 读图计算指标 → 文字结论

四、易错点

  • ⚠️ RR 中"新到达进程"与"时间片用完进程"谁先进就绪队列——通常新到达者先入队尾，再排被换下者（按题目约定，决定甘特图形状）。
  • ⚠️ 抢占式算法在每个到达时刻都要重新裁决，别只在时间片边界裁决。
  • ⚠️ 带权周转可能很大（短作业等待久时），平均带权周转 ≥ 1。
  • ⚠️ HRRN 是非抢占的；响应比在每次调度点重新计算。

五、复习建议

  1. 每种算法手算 2 组数据，画甘特图；
  2. 重点练"抢占式 + 多事件同时发生"的复杂场景；
  3. 精做 2026 真题，把"分析题"的作答格式（图 + 表 + 结论）固定下来。

例题精练（附答案）

例题 1：时间片轮转（RR）甘特图与平均周转

题目：P1（到达 0，运行 8）、P2（到达 1，运行 4）、P3（到达 2，运行 6），时间片 q = 4。画甘特图并求平均周转时间。（约定：新到达进程先入队尾，再排被换下的进程）

参考答案：

| P1(4) | P2(4) | P3(4) | P1(4) | P3(2) |
0       4       8       12      16      18

推演：P1 跑 0—4（剩 4，队列入队 P2、P1）；P2 跑 4—8 刚好完；P3 跑 8—12（剩 2）；P1 跑 12—16 完；P3 跑 16—18 完。

进程 完成 周转
P1 16 16 − 0 = 16
P2 8 8 − 1 = 7
P3 18 18 − 2 = 16

平均周转 = (16+7+16)/3 = 13。

例题 2：SJF（非抢占）对比

题目：同样三个进程，若改为"全部在 0 时刻到达"，采用非抢占 SJF，求调度顺序与平均周转。

参考答案： - 按运行时间排：P2(4) → P3(6) → P1(8)； - 完成时间：4、10、18 → 周转 = 4、10、18； - 平均周转 = 32/3 ≈ 10.67，优于 FCFS（顺序执行时 (8+12+18)/3 ≈ 12.67）。 - 结论：SJF 平均周转最优，但长作业可能饥饿。

例题 3：高响应比 HRRN

题目：0 时刻只有 P1（运行 8）到达，P2（运行 4）在时刻 1 到达。HRRN 下时刻 8 时调度谁？

参考答案： - 时刻 8（P1 刚完成）：P2 等待 = 8 − 1 = 7，响应比 R = (等待 + 服务)/服务 = (7+4)/4 = 2.75； - 只有 P2 就绪 → 调度 P2。若同时还有 P3（到达 2、运行 6）：R = (6+6)/6 = 2.0 < 2.75，仍调度 P2。 - HRRN 的直觉：等得越久、干得越快，越优先。
