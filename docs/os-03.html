OS-03 P/V 操作与进程同步

凸包顶点 · 操作系统 | 考频：6 次综合题（2010 / 2013 / 2016 / 2019 / 2022 / 2025）| 难度：★★★★ 定位：OS 的"王者顶点"——考频并列第一、难度 OS 最高，三年一循环铁律。

一、为什么它是凸包顶点

P/V 操作是 OS 凸包的右上顶点：6 次大题，几乎每三年必考，且近年出现变种 （不只是默写经典模型，还要现场设计同步方案）。它是 OS 综合题的"必修课代表"。

二、核心知识清单

2.1 信号量机制

typedef struct {
    int value;                  // 资源计数
    struct process *list;       // 阻塞队列
} semaphore;

P(S) {                          // wait(S)：申请资源
    S.value--;
    if (S.value < 0) block(S.list);   // 资源不足，阻塞
}

V(S) {                          // signal(S)：释放资源
    S.value++;
    if (S.value <= 0) wakeup(S.list); // 有等待者，唤醒
}

信号量取值含义（选择题必考）： - value > 0：可用资源数； - value = 0：资源用完，无等待者； - value < 0：|value| = 等待队列长度。

2.2 两类信号量

类型 初值 用途 位置
互斥信号量 mutex 1 保护临界区 P/V 在同一进程内成对夹住临界区
同步信号量 full/empty 0 或 n 协调先后次序 P 在消费者，V 在生产者，分居两进程

军规：先检查同步（资源），再检查互斥（mutex）——同步 P 在前，互斥 P 在后，否则可能死锁。

2.3 三大经典模型（必须默写）

① 生产者—消费者（缓冲池 n 格）：

semaphore mutex = 1, empty = n, full = 0;

producer() {
    while (1) {
        生产一个产品;
        P(empty);          // 等空位
        P(mutex);          // 进临界区
        放入缓冲池;
        V(mutex);
        V(full);           // 产品 +1
    }
}

consumer() {
    while (1) {
        P(full);           // 等产品
        P(mutex);
        取出产品;
        V(mutex);
        V(empty);          // 空位 +1
        消费产品;
    }
}

② 读者—写者（读者优先，readcount 版本）：

semaphore rw = 1, mutex = 1;   // rw 锁数据库，mutex 锁 readcount
int readcount = 0;

reader() {
    P(mutex);
    if (++readcount == 1) P(rw);   // 第一个读者锁写
    V(mutex);
    读;
    P(mutex);
    if (--readcount == 0) V(rw);   // 最后一个读者释放
    V(mutex);
}
writer() { P(rw); 写; V(rw); }

③ 哲学家就餐（防死锁方案：限制同时取筷人数 / 奇偶取筷顺序 / 同时取两支）：

semaphore chop[5] = {1,1,1,1,1};
semaphore room = 4;            // 方案一：最多 4 人同时取筷
philosopher(i) {
    P(room); P(chop[i]); P(chop[(i+1)%5]);
    吃;
    V(chop[i]); V(chop[(i+1)%5]); V(room);
}

2.4 死锁

  • 四条件：互斥、不可剥夺、请求并保持、循环等待（缺一不可）；
  • 处理：预防（破条件）/ 避免（银行家算法，安全序列）/ 检测解除（资源分配图）。

三、解题五步法（综合题标准动作）

1. 找角色：有几类进程，各干什么
2. 找资源：什么需要互斥（mutex=1），什么需要同步（计数）
3. 定初值：每个信号量初值 = 初始可用数量
4. 写代码：P 申请 / V 释放，同步 P 先于互斥 P
5. 做检查：任一执行交错下不死锁、不违反约束

四、易错点

  • ⚠️ P/V 顺序：先 P 同步信号量，再 P 互斥信号量；V 顺序无严格要求但习惯对称。
  • ⚠️ 读者—写者中 readcount 本身也是临界资源，需要 mutex 保护。
  • ⚠️ "value<0 时阻塞"的 if 判断写错（注意是 < 还是 ≤，P 用 <0，V 用 ≤0）。
  • ⚠️ 变种题（2022/2025）：给的具体约束要翻译成额外信号量，别硬套模板。

五、复习建议

  1. 三大模型达到"3 分钟默写无错"；
  2. 精做 2010/2013/2016/2019/2022/2025 六道真题，感受从"经典"到"变种"的演变；
  3. 每周自造一道同步题（如：理发店、公交车司机售票员、水果盘）并完整求解。
