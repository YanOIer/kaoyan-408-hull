# CO-03 Cache 与存储层次

> 凸包顶点 · 组成原理 | 考频：5 次综合题（2013 / 2017 / 2020 / 2021 / 2025）| 难度：★★★★
> 定位：组原计算题第一大户，也是 CO×OS 跨科链路（Cache–主存–虚存–TLB）的中枢。

---

## 一、为什么它是凸包顶点

Cache 考频 5 次、几乎"隔年必考"，且每考必是完整计算大题。它向上承接虚存
（OS 内存管理），向下触及主存组织，是凸包右上区最"厚实"的顶点：
**Cache 题 = 地址划分 + 命中判断 + 性能计算**，三步走通了就是稳定 10 分。

---

## 二、核心知识清单

### 2.1 地址划分（一切的起点）

主存地址 = | 标记 Tag | 组号/行号 Index | 块内地址 Offset |

| 映射方式 | 地址结构 | 特点 |
|---------|---------|------|
| 直接映射 | 标记 + **行号** + 块内 | 每组 1 行，冲突最多，硬件最简单 |
| 全相联 | 标记 + 块内 | 任意放，冲突最少，比较器最贵 |
| 组相联 | 标记 + **组号** + 块内 | 折中；n 路 = 每组 n 行 |

**速算**：块内地址位数 = log₂(块大小)；组号位数 = log₂(组数)；剩下全是标记。
`组数 = Cache行数 / 相联度`，`Cache行数 = Cache数据容量 / 块大小`。

### 2.2 命中与性能计算

```
命中率 h = 命中次数 / 总访问次数
平均访问时间 Ta = h·Tc + (1−h)·Tm        （先访问 Cache，缺失再访主存）
              或 = Tc + (1−h)·Tm         （看题目是否重叠，读题！）
```

- Tc：Cache 存取时间；Tm：主存存取时间（或缺失损失）。
- **效率 e = Tc / Ta**。

### 2.3 替换算法与写策略

| 替换算法 | 实现 | 特点 |
|---------|------|------|
| 随机 | 简单 | 不公平 |
| FIFO | 队列 | 可能 Belady 异常 |
| **LRU** | 计数器/栈 | 命中率高，408 最常考 |
| LFU | 访问计数 | 开销大 |

写策略：
- **写直达 WT**：同时写 Cache 和主存（一致性好，常配写缓冲）；
- **写回 WB**：只写 Cache，**脏位=1** 的行被替换时才写回主存（省带宽）。

写缺失：写分配（先调入 Cache）vs 非写分配（直接写主存）。

### 2.4 跨科链路（408 特色综合点）

```
CPU 给出 VA ──TLB/页表──→ PA ──Cache 地址划分──→ 命中? 读数据 : 访主存
                ↑OS 内存管理        ↑CO 存储层次
```

虚拟 Cache / 物理 Cache、TLB 与 Cache 的访问次序，是 CO×OS 交界的高阶考点。

---

## 三、典型考法

1. **地址划分**：给容量/块大小/相联度，求 Tag/Index/Offset 各几位（必考）。
2. **命中过程追踪**：给一串地址访问序列，判断每次命中/缺失、画出最终 Cache 内容。
3. **性能计算**：求命中率、平均访问时间、加速比。
4. **综合**：Cache + 虚存 + 磁盘一条链（2020/2025 风格），跨科大题。

---

## 四、易错点

- ⚠️ Cache 容量题目给的是**数据部分**，不含标记位/有效位阵列（除非明说"总容量"）。
- ⚠️ 直接映射的"行号"和组相联的"组号"位数不同，别混。
- ⚠️ LRU 模拟时**每次访问（命中也算）都要更新**使用次序。
- ⚠️ 写回法替换时先检查脏位——脏行要写回主存，影响总时间。
- ⚠️ "按字节编址"还是"按字编址"决定块内地址位数，审题第一刀。
